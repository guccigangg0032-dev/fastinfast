# Отдельная рабочая ветка: калькулятор и возврат со страховщика
Статус: интерфейс и серверный адаптер **подготовлены**, действующий расчёт **не подключён**. Сайт **не опубликован**. Эта ветка создана из приостановленного `main`, а `index.html` восстановлен из сохранённой версии для разработки. На `main` не вносить изменений и не подключать `preview.asia` без отдельного согласования: домен используется в другом проекте.

## Сейчас работает в локальной ветке
- Собственный выбор компании, региона, категории авто и даты без ИИН.
- Кнопка официального сайта открывает страховщика в новой вкладке, сохраняя исходную вкладку. В Safari/iPhone возврат выполняется через переключение вкладок. Принудительное закрытие/возврат с чужого домена без поддержки партнёра невозможны.
- Если задать публичный URL сервера `apiBaseUrl` в `quote-config.js`, кнопка «Рассчитать стоимость» POST-ит публичные параметры на защищённый Worker. Сайт показывает сумму **только после действительного ответа**. Пока конфигурация пустая, кнопка отключена, выдуманной цены нет.
- Для настоящего онлайн-расчёта через страховщика нужен одобренный API/виджет или другой разрешённый договором канал. Для серверного Worker нужен API контракт: поля запроса, авторизация, ответ, лимиты, consent-flow, права на обработку данных.

## Cloudflare Worker (пример, не деплоить без договора)
`worker/insurance-quote.js` принимает только перечисленные публичные поля, исключает ИИН, токены SMS, банковские данные, не логирует персональные данные. Переменные окружения:
- `ALLOWED_ORIGIN`: HTTPS-адрес **отдельного разрешённого сайта** (не `preview.asia` по умолчанию).
- `INSURER_ID`: `halyk`, `nomad` либо `eurasia` только при реальном API этого страховщика.
- `INSURER_QUOTE_URL`: HTTPS URL документированного авторизованного метода расчёта (не страница браузера).
- `INSURER_API_TOKEN`: секрет только на сервере.
Схема ответа провайдера в коде помечена как адаптируемая и требует проверки. Worker является **примером интеграционного интерфейса**, а не рабочим подключением. Перед продуктивным запуском нужны надёжная аутентификация сессии, anti-bot, rate limiting, мониторинг доступности, защита от повторных запросов, локальные правовые требования к данным и отдельные адаптеры на каждого страховщика.

## Статус 1414 / КДП / оплата
Эта ветка не инициирует SMS 1414 и не собирает ИИН, сканы документов, коды или реквизиты; оплата и выпуск полиса отсутствуют. Для реального доступа к персональным данным нужен надлежащий законный механизм согласия, а для выпуска ОГПО ВТС нужно соблюсти специальный режим посредничества/электронного страхования. Проверить действующую редакцию статьи 12-1 Закона РК об ОГПО и законодательство о страховой деятельности перед запуском.

## Проверка вручную
1. Открыть `index.html` в локальном web-сервере, проверить адаптивность и выбор страховщика.
2. Убедиться, что без настроенного backend кнопка «Рассчитать стоимость» заблокирована.
3. Открыть официальный сайт страховщика в отдельной вкладке и проверить сохранение исходной вкладки.
4. Подключить **тестовый разрешённый** API страховщика через Worker и проверить корректную стоимость, 503, 502, timeout, неправильный ответ, изменение полей.
5. Ничего не публиковать до проверки правового статуса, реквизитов и передачи персональных данных.
