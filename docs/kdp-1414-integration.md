# Fast Insurance Online: 1414 / КДП / расчёт ОГПО
Статус: **проект интеграции, не подключено**. Нельзя считать отображение раздела на сайте рабочей государственной проверкой.

## Цель
После обращения через Fast Insurance Online клиент должен иметь возможность дать адресное согласие на доступ к данным через SMS от 1414 и получить корректную стоимость ОГПО ВТС, не выдавая свои ЭЦП, не пересылая скриншоты SMS и не заходя в чужой аккаунт.

## Пользовательский сценарий
1. Клиент выбирает ОГПО и знакомится с названием организации, перечнем запрашиваемых персональных данных, целью и сроком обработки.
2. На **защищённом серверном приложении**, а не в статическом GitHub Pages, вводит ИИН и номер, зарегистрированный в Базе мобильных граждан (БМГ). Ввод необязателен для ориентировочного публичного калькулятора, если там не используются персональные сведения.
3. После получения информированного согласия на инициирование запроса и проверки законных оснований сервер запускает **официальный** запрос КДП от зарегистрированной организации, через одобренную интеграцию. Никаких самостоятельных SMS от имени 1414.
4. Пользователь получает SMS **от 1414**: внимательно сверяет организацию и предмет доступа. В распространённой схеме КДП **511 = согласие**, **512 = отказ**. Текст конкретной актуальной SMS приоритетен.
5. Бэкенд получает официальный статус согласия по корреляционному идентификатору запроса. Статусы: pending, approved, declined, expired, error. Никогда не определять «approved» по нажатию кнопки или сообщению пользователя «я отправил 511».
6. Только при реальном approved вызывается разрешённый API партнёра-страховщика для получения сведений, класса бонус-малус и расчёта. Данные можно запрашивать строго в пределах согласия и договоров.
7. На сайте показываются название страховщика, цена, дата актуальности и ограничения расчёта. Сам полис и его оплата допускаются только в официально согласованном процессе страховой организации.

## Разделение интеграций
- **КДП / 1414**: согласие гражданина на доступ к персональным данным. Это **не** ЭЦП, не подписание полиса и само по себе не подтверждение авторизованной сессии пользователя.
- **NCALayer**: отдельный механизм работы с ЭЦП на поддерживаемом устройстве; для сценария согласия по SMS он не обязателен.
- **Биометрия**: альтернативный механизм идентификации/согласия, требует отдельной разрешённой интеграции.
- **API страховщика / ЕСБД**: получение разрешённых данных и итогового тарифа. Нельзя считать полную цену лишь из ИИН и ответа 511 без страховщика и дополнительных сведений.
- **Сервер**: формирует короткоживущую защищённую сессию, хранит статусы, проверяет ответы КДП, не размещает ключи и ИИН в публичном JavaScript. Ограничение запросов, аудит, HTTPS, конфиденциальность, сроки хранения.

## Что требуется для запуска
- Установить юридический статус оператора сайта (ИП, агент/партнёр страховщика), основание доступа к сведениям и согласованный объём данных.
- Получить у партнёра-страховщика документированную возможность использовать его API/KДП или самостоятельно пройти процедуру подключения КДП через **Smart Bridge** (https://sb.egov.kz/) с необходимыми проверками и договорами.
- Получить документированное описание API расчёта ОГПО, статусов/ошибок и подтверждение разрешённого партнёрского тарифа. Для обязательной страховки окончательная премия рассчитывается по закону и действующим коэффициентам.
- Развернуть защищённый бэкенд: **GitHub Pages сам по себе не выполняет серверные запросы к защищённым государственным API**.
- Юридическая проверка наценки ИП, агентского вознаграждения, маршрута оплаты, текста согласия на обработку данных и политики конфиденциальности.

## Принцип интерфейса сейчас
Раздел «Согласие через 1414» — **описание будущего процесса**, а не авторизация.
ИИН, фото лица, SMS и документы **не запрашиваются и не сохраняются**. Форма на сайте лишь готовит текст обращения локально, не отправляет его на сервер.
