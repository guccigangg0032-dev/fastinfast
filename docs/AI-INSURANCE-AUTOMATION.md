# Целевая схема страхового ИИ-бота: документы → стоимость → оплата

**Статус: проектное задание, НЕ работающая интеграция.** Выполнение ограничено официально разрешёнными API/партнёрскими сценариями KMIC и KupiPolis/Сентрас Иншуранс. Доступ промоутера Tumar не даёт автоматического разрешения работать от имени страховщика или клиента.

## Клиентский путь

1. Клиент выбирает KMIC MyHome или KupiPolis ОС ГПО ВТС.
2. Страховой помощник задаёт минимальное число вопросов. Только после согласия на конкретные цели обработки и передачи третьим лицам клиент загружает документы (для ОС ГПО — техпаспорт и водительские документы, если действительно требуются страховщику). Для MyHome набор документов нужно уточнить отдельно.
3. Защищённый сервер (не GitHub Pages) принимает загрузку. Проверяет тип, размер, вредоносные вложения, изолирует доступ, шифрует хранение и удаляет по установленному сроку. Содержимое не отправлять в общедоступные LLM/API. Локальная OCR/vision модель извлекает поля, человек проверяет и подтверждает перед отправкой. Журналировать только технические события без ПДн.
4. Запросить у уполномоченного страховщика тариф и факторы расчёта через согласованный API. Вариант управляемой браузерной автоматизации возможен **только с официальным разрешением владельца портала** и без обхода защиты, CAPTCHA и двухфакторной аутентификации. Не использовать секреты промоутера в публичном сайте.
5. Если нужна КДП/1414, открыть официальную страницу авторизации, где клиент сам подтверждает запрос. Не собирать SMS-код или ЭЦП на нашем сайте. Подтверждение результата принимать только через разрешённый API/подписанный callback или вебхук.
6. Сервер получает подтверждённую актуальную стоимость, источник тарифа, срок актуальности и идентификатор предложения. Отображает клиенту на нашем сайте **ровно подтверждённую** цену без выдуманных коэффициентов. При отсутствии ответа показать «Не удалось получить расчёт», не подставлять примерную цену.
7. Клиент оплачивает через официальную защищённую платёжную страницу страховщика/эквайера (или разрешённый встроенный checkout с токенизацией). Наш сервер не хранит номер карты, CVV или полные платёжные реквизиты.
8. После подтверждения платежа через подписанный webhook/статус от страховщика вернуть на наш сайт состояние «Оплачено» и предусмотренную страховщиком ссылку на полис. Не объявлять оплату успешной по одному лишь возврату браузера.

## Требуемые доступы

- Подписанный партнёрский договор и документация API для KMIC MyHome.
- Подписанный партнёрский договор и документация API для KupiPolis/АО «Сентрас Иншуранс» по ОС ГПО ВТС.
- Явно согласованные цели и полномочия на получение/передачу персональных данных и автоматизацию.
- Расчёт тарифа и класс бонус-малус (где требуется): только официальные источники и после необходимых согласий.
- Схема КДП/1414: кто инициирует согласие, какую организацию увидит клиент, как передаётся результат.
- Согласованная платёжная интеграция, возврат/вебхук, подпись ответа, срок действия цены.
- Политика конфиденциальности, аудит безопасности и защищённый бэкенд с учётом законодательства Казахстана.

## Разделение ролей ИИ и интеграций

**Qwen**: общение, объяснение, помощь с выбором, структурирование и проверка OCR-полей, помощь в заполнении после согласия клиента.

**OCR/vision**: извлечение структурированных сведений из документа с подтверждением пользователем. Не отправлять фотографию целиком в незнакомые сторонние сервисы.

**Интеграционный модуль**: API KMIC/KupiPolis, документированный workflow КДП, статусы и платёжные вебхуки.

**Qwen не является** источником официальной страховой цены, не запускает произвольные действия в чужом аккаунте и не заменяет разрешение партнёра.
