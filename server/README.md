# Локальный Qwen для страхового чата — подготовка, не запуск

В черновой ветке сайта виджет чата работает в справочном режиме без ИИ. Для настоящего Qwen понадобится защищённый backend. GitHub Pages не поддерживает выполнение Python или Ollama.

## Локальная проверка

1. Убедитесь, что Ollama или другой поддерживаемый сервер модели запущен на доверенном компьютере. Проверьте установленную модель через `ollama list`. Не предполагайте, что модель называется `qwen3:4b`; задайте `QWEN_MODEL` согласно реальному имени.
2. В каталоге `server` создайте виртуальное окружение и установите `pip install -r requirements.txt`.
3. Запустите `uvicorn qwen_assistant:app --host 127.0.0.1 --port 8788`. По умолчанию код обращается к локальному `http://127.0.0.1:11434/api/chat`.
4. Только после настройки защищённого **same-origin** reverse proxy, который сопоставляет `https://preview.asia/api/assistant` с локальной службой, добавьте в тег `<html>` атрибут `data-ai-endpoint="/api/assistant"`.
5. Прежде чем открывать сайт, подключите HTTPS, контроль доступа к серверу, WAF/ограничение запросов, журналирование **без ПДн**, и выполните тесты безопасности. CORS не должен допускать сторонние домены. Не публикуйте порт Ollama 11434.

Здесь **нет** доступа к Tumar Promoter, Freedom, КДП 1414 или API KMIC/KupiPolis. AI не авторизует клиента, не рассчитывает официальную страховую премию, не оформляет и не оплачивает полис. Любой доступ к кабинету или данным бонус-малус требует разрешения владельца системы и отдельного документированного API.

Не посылайте ИИН, телефон, документы, платёжные данные или коды из SMS в чат. Проверка регулярными выражениями — дополнительная защита, а не полноценная DLP/защита персональных данных. Перед публичным использованием нужна политика обработки данных, безопасный контур и тестирование. База знаний и роли модели — только справочное сопровождение.

Сайт остаётся снятым с публикации: все изменения только в ветке `draft-kmic-kupipolis-forms`.
